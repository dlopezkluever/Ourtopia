# Durable deadlines, notifications, and background work

Business records store UTC due times for Invite expiry, reservation acknowledgment, scheduled Handoff and Return, missing confirmation review, and vote closure. A command checks a deadline when it acts, even if a scheduled worker has not run. Invite redemption and reservation acknowledgment cannot succeed after their due times. Supabase Cron periodically finds due records and invokes the same guarded commands used by interactive actors with a server identity. Each command locks and rereads current state and time before it changes anything. A stale worker call is a no-op or returns the recorded result. The clock does not appear in a reservation uniqueness predicate.

The transition transaction inserts notification intents into a durable outbox with a unique key for the source event, recipient, channel, and notice kind. Workers claim pending entries, record attempts, and retry failures. They create in-app notices and send required email after the business transaction commits. Reminder jobs use the current schedule and a stable reminder identity, so a reschedule invalidates stale work and cannot send an obsolete notice. Delivery failure never changes an Exchange, Dispute, vote, or membership result. Administrators can inspect failed delivery status. The worker may run late; a deadline guard, not the worker's timing, decides whether a command is valid.
