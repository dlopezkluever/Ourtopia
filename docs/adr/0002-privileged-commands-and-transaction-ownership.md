# Privileged commands and transaction ownership

The browser sends an authenticated intent to one server command. It does not assemble a state transition from direct Supabase writes. A Postgres command function owns each privileged transition and performs authorization, current-state and deadline checks, state changes, audit and domain event inserts, reputation effects when due, and notification outbox inserts in one transaction. The command returns the resulting state or a typed authorization, validation, conflict, or expiry error. A stable intent identity identifies a retry by the same actor with the same payload; reuse with different intent fails. Commands also reject stale expected state. Direct client writes to command-owned state, audit, reputation, vote results, and billing status are denied.

Edge Functions may authenticate requests, verify Stripe signatures, call a command, and deliver external effects. They do not split one transition into several database calls. A command that uses elevated database rights checks the actor and Community scope itself and has narrow execute grants. Background workers call the same guarded commands with a server actor. Email delivery and other external calls occur after commit from the outbox; failure cannot roll back the business transition. [ADR 0007](0007-durable-deadlines-notifications-and-background-work.md) defines the retry pattern for those effects.
