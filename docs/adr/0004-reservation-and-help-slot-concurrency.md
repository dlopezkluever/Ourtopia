# Reservation and help-slot concurrency

An item Borrow Request uses inclusive calendar dates in the UI. Postgres stores the reserved dates as a half-open date range, from the first requested date through the day after the last requested date. Approval creates a reservation for one item Listing and a 48-hour acknowledgment deadline in the same transaction. Reservations block overlapping approvals while the Exchange is `approved`, `handoff_pending`, `checked_out`, or `return_pending`, and while custody remains unresolved after closure. The command changes the reservation's stored blocking status with the Exchange state and custody decision. A database exclusion constraint on Listing identity and the range of blocking reservations rejects overlap, including concurrent approvals. The constraint does not depend on the current clock or a join to Exchange state. Approval also checks current item custody, so an overdue item still held by a borrower cannot receive a new approval merely because its planned end date passed.

The acknowledgment command succeeds only before its deadline. The expiry command succeeds only after the deadline while the Exchange remains unacknowledged. Both lock and recheck the same Exchange and reservation; exactly one wins a race. Acknowledgment retains the reservation. Expiry and pre-handoff cancellation release it. A confirmed physical Return releases the reservation. A disputed or missing Return keeps the item unavailable until an administrator records recovery; closing an Exchange without verified completion does not by itself release the item. The owner cannot edit a blocking reservation's dates outside the same guarded allocation command.

A Help Need Post stores its requested helper count. Acceptance locks that Need Post, checks the remaining places, and creates one Help Exchange and one accepted slot for the helper in the same transaction. A unique identity prevents the same helper from taking two active places on one post. Concurrent acceptances cannot exceed the requested count. Cancellation closes that helper's slot and makes the place available again without deleting the Exchange history. Help Listings have no Need Post slot cap; each accepted requester still receives a separate Help Exchange. [ADR 0008](0008-exchange-domain-model.md) defines the shared Exchange identity.
