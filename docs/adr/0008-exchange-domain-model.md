# Exchange domain model

Item loans and help commitments share one Exchange identity. Each Exchange has an immutable Community, kind (`item` or `help`), two named participants, its source Listing or Need Post, current kind-specific state, and an append-only event history. Disputes, thank-yous, Qualifying Interactions, and Reputation Events reference that identity. A Borrow Request remains a separate application; approval creates its item Exchange. Each accepted helper creates a separate help Exchange, including when several helpers answer one Need Post.

An item Exchange names an owner and borrower and has item-only terms, reservation, Handoff, Return, condition, and optional photo records. A help Exchange names a requester and helper and has help-only schedule and completion records. For a Help Listing, the Listing owner is the helper and the committing member is the requester. For a Help Need Post, its author is the requester and the accepted member is the helper. Kind-specific detail records and constraints reject item fields on help Exchanges and missing required item or help fields. Shared completion and Dispute relationships do not merge the two state machines or award rules.
