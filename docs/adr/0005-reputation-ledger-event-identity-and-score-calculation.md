# Reputation ledger, event identity, and score calculation

[ADR 0001](0001-global-and-community-reputation.md) defines the score formula. This decision defines its records. Verified Reputation Events form an append-only ledger with recipient, Community, event type, points, source kind and identity, creation time, and the command or administrator decision that verified the event. An automatic event has a unique semantic identity consisting of its rule, source, and recipient. A completed Exchange, a thank-you, and a verified misconduct decision may therefore produce separate events even when they relate to the same Exchange. Each completed Exchange also produces at most one Qualifying Interaction fact per participant. Retries reuse those identities and cannot add points or counts twice.

A correction appends an event linked to the event it corrects, with a reason, authorizing administrator, and its own unique correction identity. It never edits or deletes the original. The effective score sums original and compensating points. A Dispute opened after completion may add or correct points but does not erase the completed Exchange's Qualifying Interaction. The server calculates Community scores from indexed ledger rows and Global scores from those Community results and Qualifying Interaction counts on demand for the pilot. It does not keep a separately writable score table. An owner approval command calculates the candidate's current local score inside its guarded transaction before applying the Listing minimum. Cross-Community reads return the redacted result from [ADR 0003](0003-authorization-cross-community-disclosure-and-removed-member-access.md); they do not expose foreign ledger rows. A later materialized score would need a new decision and use the same ledger as its authoritative record.
